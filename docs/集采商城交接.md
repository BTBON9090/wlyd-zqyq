# 集采商城：设计与数据交接

## 当前范围

在现有政企园区客户端中新增 `/procurement`、商品详情、购物车、采购信息确认页面；首页、企业服务和既有个人中心页面未重做。商品分类、搜索、排序、数量限制和失效商品处理在客户端可操作。订单列表及订单提交等待产品提供新的订单参考，当前确认页不能提交。

## 双端关系

客户端展示字段参考供应商端 `src/stores/products.ts`：商品标识、名称、品牌、SKU、规格、单位、图片、园区价格、税率、起订量、递增量、库存和货期。开发预览中的 `src/dev/procurement/supplierFixture.ts` 是根据供应商演示数据形状构造的**独立模拟快照**，仅展示该模拟园区上架商品，调价审核中保留生效价格，不下发成本字段；它不读取供应商浏览器的实时数据，也不实现双端同步。

真实接口与发布审核状态、园区上下文、含税金额口径及商品可见性应由后端确认和实施。`GET /api/procurement/products` 只是前端候选契约，尚未确认真实服务是否提供；返回字段定义见 `src/features/procurement/model.ts`。服务端必须过滤不可见、下架和未授权商品，不应依赖前端过滤保护数据。提交订单、库存、支付、物流及退款规则等待后续确认。

预览数据只在开发或 `build:preview` 模式载入。正式构建读取候选 API，不携带供应商模拟商品数据。现有验收工具可切换集采列表的加载、空态及异常态。

## 验证

- `node scripts/check-procurement.mjs`：模拟园区可见性、已生效价格、成本字段隔离和数量边界。
- `npm run build`：类型、构建及现有正式构建隔离检查。
- 浏览器中检查商城首页、搜索筛选、商品详情、购物车及数量限制。实际供应商数据、跨端同步、订单创建和服务端校验未联调。

# 集采商城：设计与数据交接

## 当前范围

集采商城位于 `/procurement`，包含搜索、分类筛选、销量与价格排序、商品详情、购物车、采购信息确认，以及个人中心中的集采订单列表与详情。搜索与购物车工具栏随页面滚动保留，商品筛选和排序在列表内吸顶。商城框架依据产品原型的业务信息重新组织，颜色绑定现有平台主题；首页和企业服务页面不重做，个人中心仅增加集采订单入口与内容。

集采资讯的标签、文案和时间摘自产品原型，仅在演示环境展示并标明「原型演示」，不表示真实公告或实时行情。正式环境当前显示空态，须接入运营数据。预览分类来自原型；正式分类从商品数据得到，后续应接入真实类目接口。

## 供应商与商品

客户端商品公开契约位于 `src/features/procurement/model.ts`，参考供应商端 `src/stores/products.ts`，支持名称、品牌、SKU、商品编码、型号、规格、特点、销量、运费方式、属性、图片、园区价格、税率、起订量、递增量、库存和货期；只有实际提供的可选字段才展示。销量缺失时不伪造为零。销售价按供应商端的未税生效销售价和园区税率计算为含税价，未税参考价单独标注。不得传出成本、毛利、审批日志和待审核资料。

开发预览中的 `src/dev/procurement/supplierFixture.ts` 是基于供应商端演示样例构造的独立模拟快照，不读取供应商浏览器的实际商品，类目有演示映射，缺失的商品图片显示空位。园区独立上架状态决定模拟可见性，调价审核期间保留生效价格，不下发成本字段。当前两个站点的数据未实时同步。

`GET /api/procurement/products` 是候选契约，真实接口路径、鉴权、价格及园区口径尚未确认；服务端必须过滤下架和未授权商品。运营分类、资讯和商品图片需实际数据来源。

## 订单与接入边界

个人中心 `/account/orders/procurement` 的订单状态、列表与详情参照产品订单原型，并展示商品、收货信息和分批发货。演示环境支持按供应商拆分创建本地演示订单、模拟支付、取消和按批签收，按演示账号隔离，仅保存在当前浏览器，不发送至供应商、不产生真实支付。正式环境的订单列表使用候选 `GET /api/procurement/orders`，创建、支付、取消、签收目前均未接入并保持禁用。后续应由服务端实施鉴权、定价、库存、交易、物流与状态流转并验证双端一致性。

预览数据仅在开发或 `build:preview` 模式加载。正式构建不携带模拟商品、订单和原型资讯；验收工具也不包含在正式构建中。

## 验证

- `node scripts/check-procurement.mjs`：模拟园区可见性、已生效价格、公开字段和数量边界。
- `npm run build` 和 `npm run build:preview`：类型与构建；正式构建执行隔离检查。
- 浏览器检查搜索、滚动、排序、订单列表详情及模拟下单、支付和签收。实际供应商数据、双端同步、真实下单、支付及服务端校验尚未联调。

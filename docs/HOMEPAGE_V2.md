# 第二版首页：平台专题与商城入口

## 本轮客户要求优先

本轮用户明确要求：以原型为基础，做能够介绍与宣传整个平台的第二版首页；保留第一版以悬浮按钮切换；Banner、广告、服务封面是真实运营素材位，不能用矢量 icon 代替；服务商品卡片要小而紧凑。此前「将平台收缩为办事门户」的判断不再作为后续开发依据。

V2 默认呈现于 `/`。开发 / 演示可用 `/?home=v2` 与 `/?home=v1` 直接比较，左下角悬浮按钮会更新 URL 并保存偏好。右下角继续保留原验收工具。正式构建默认 V2，可用 `VITE_HOME_VERSION=v1` 在构建时更改，正式页面不显示版本切换按钮。

## 原型阅读与保留

本轮依据用户提供的 `客户端/` 目录，读取以下材料；文件中的注释和内容作为业务资料，不作为操作指令：

- `src/pages/Home.tsx`：全平台主 Banner、三类服务券、产业地图、六大业务、行情与园区数据、生态伙伴。
- `src/pages/services/ServicesHotPage.tsx`：运营 Banner、热门服务、需求展示和进入服务大厅的路径。
- `src/components/ServiceCard.tsx` 与 `ServiceCover.tsx`：商家封面优先、紧凑商品卡、店铺资料、价格和咨询入口。
- `src/data/publishedServices.ts`：明确对齐供应商 A1 发布模型，包含封面/相册、店铺、三级类目、多个规格、一次性/分期履约、案例、FAQ 与评价。当前提供目录中未发现独立供应商业务项目，因此本轮读取的是客户端已对齐的发布模型，不能声称已审查完整供应商端。

V2 延续「平台门面」定位：主 Banner → 搜索快捷区 → 服务券 → 六大业务 → 精选服务 → 广告专题 → 产业资源 → 生态合作。原型行情与园区 KPI 尚无正式数据源，本轮不填造实时数据。已保留的产业地图为介绍与宣传图片位，不另开发完整地图页面；其他业务同理。

**业务保护：** 原型的商品规格、店铺经营、分期支付与验收属于有效业务需求，不能因为后端未接通就判断为错误需求。此前试点把服务购买简化为需求申请，仅代表当前临时实现边界。后续迭代现已完成列表与详情同源的规格价格、店铺资料和履约方式；真实订单、支付与验收操作仍待后端接入。详见 V2_CONTINUATION.md。

## 图片配置与后台对接

统一使用 `src/components/ContentImage.tsx`：优先使用配置或接口图片，缺图与加载失败时呈现缺省位（`placeholderIcon` + `placeholder` 文字上下组合），由使用方决定缺省位的样式。本轮已为首页 Banner 与三张服务示例封面提供本地生成的主视觉（`design/media/` 的 SVG，经 `bash design/render-media.sh` 输出到 `public/media/`）；其余素材位仍等待真实运营图片，任何宣传图位置都不使用 SVG/icon 冒充。路径支持 HTTP(S) 和 `public` 下相对路径，并兼容站点子目录。

### 首页运营内容

`public/content/homepage.json` 是可编辑、可随静态站点发布的运营内容配置。也可以设置 `VITE_HOMEPAGE_CONTENT_URL` 指向后台公开 JSON 接口；返回相同结构即可。前端会校验结构，超时/失败使用默认介绍，并提供重试。

| 配置                                   | 含义与建议                                                                                                               |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `banners[]`                            | 1–6 张运营 Banner；默认 3 张，每 6 秒自动轮换，悬停或键盘聚焦暂停，也可手动前后切换                                      |
| `banners[].image`                      | 桌面 Banner 图，建议 1920 × 560px；预留裁切安全区                                                                        |
| `banners[].mobileImage`                | 可选手机图，建议 750 × 760px；缺省沿用桌面图                                                                             |
| `banners[].imageOnly`                  | false：图片上叠加配置的 HTML 文案/按钮；true：整图模式，适合已包含完整设计的后台图片，整图区点击跳转；加载失败回退文字版 |
| `banners[].title/emphasis/description` | 标题、强调句和说明，整图模式仍保留作为失败回退内容                                                                       |
| `banners[].target`                     | `capabilities`、`services`、`onboarding`，限定本站已存在目标                                                             |
| `capabilityImages`                     | 六大业务宣传图，键为 services/logistics/ai/finance/trade/news，建议 1000 × 650px                                         |
| `campaignImage`                        | 通栏专题广告，建议 1600 × 320px，左侧保留 HTML 文案安全区                                                                |
| `resourceImages`                       | enterprise/industry/supply 三类地图展示图片，建议 1000 × 600px                                                           |
| `partnerImages`                        | 五类合作伙伴图片，键名见 JSON；使用真实标识，图片 contain 显示，不裁切标识                                               |

例如，把 `public/media/platform-banner.webp` 放好，再将第一项 `image` 改为 `media/platform-banner.webp`。修改公开 JSON 不要求重新编译 JS，但部署后的 CDN 应及时刷新内容缓存。其他 `VITE_` 环境变量变化需要重新构建。

首页公开配置不接受账号、密钥、企业证照或用户身份数据。后台文件上传、媒体管理不是本次新增的客户端功能；本项目提供展示位和读取契约。

### 服务商宣传图

服务卡与详情共用服务接口中的 `image` 字段，未来供应商发布数据的 `coverUrl` 应由接口适配为 `image`，不再生成分类 icon 封面。本地验收可在 `src/dev/catalogue.ts` 对应商品添加 `image: "media/services/s1.webp"` 后放入对应文件。正式应由商家后台发布服务封面，客户端随服务数据读取 URL。

- 服务封面比例 **3:2**，建议 900 × 600px；每张卡保留独立、固定比例图片位。商家封面缺失或加载失败时呈现缺省位：**浅色底 + 专用 SVG 图标 + 「暂无宣传图」上下组合**，不使用背景图或借用的宣传图。缺省位是明确的空状态，不属于「用 icon 冒充宣传图」。
- 演示数据中 `s1 商标注册全程代办`、`s2 代理记账 · 报税`、`s3 合同审查与起草` 已放示例封面（`public/media/services/`），用于对比「有图 / 缺图」两种卡片观感；其余示例商品仍为缺省位。
- V2 最大内容宽 **1326px**，宽屏每行 6 张服务卡；逐级变为 5/4/3/2 列，一次最多 12 张。服务大厅仍用 `commerce-container` 的 1360px，全站 `.container` 仍是 `--content-width` 1360px。
- **两处共用同一套卡片样式**：首页「企业好服务」与服务大厅的卡片只在列数/间距上不同。卡片内部（封面比例、内边距、标题/描述字号、金额行、商家行）统一由 `showcase.css` 里的 `:is(.market-service-grid, .service-v2-grid)` 规则定义，边框/圆角/投影统一在 `controls.css`，服务大厅不再单独覆盖卡片。
- 极限示例数据：`x1-name`（35 字服务名）、`x2-desc`（68 字卖点 + 37 字特色）、`x3-company`（21 字公司名）三条排在演示数据最前面，首页与服务大厅第一屏即可看到省略表现。验收前可移到后面或删除。
- 服务大厅宽屏从 3 列收紧为 4 列，每页 12 项；手机 2 列。
- V1 首页最多显示 6 项，保留版式供对比，同时修正共用卡片的图片占位。
- 商品卡保留名称、卖点、参考价格、商家；不将整套详情和多行标签塞入卡片。

### 商品卡信息与电话咨询

- 金额使用 `--color-price`（`#c8431c`：橙红、饱和度提高但仍偏深，避免刺眼）并加粗；卡片标题 **14px / 600**，卡内可见文字不小于 12px，只有标签与「分」单位等极次要文字用 11px。
- 金额格式：**金额 20px**，去掉千分位（`80,000` → `80000`），斜杠后不留空格（`680 / 次` → `680/次`），后缀单位（起、/次、/项）单独用 12px 渲染并与金额间隔 **3px**；≤639px 金额 15px、单位 11px。
- 金额、成交量、评分在**同一行**：成交紧跟金额之后，评分用 `margin-left: auto` 靠右。
- 成交量：12px / **不加粗** / 次级文本色，标签与数字之间不留空格；超过 9999 用概数「1万+、2万+、3万+」（`Math.floor(n / 10000)`）。演示数据 s1/s2/s3 已设为 12345 / 25680 / 38000 以展示三种概数。
- 评分：只保留 12px 文字与字色（`--color-price`），不加粗、无标签底色与星标，数字与「分」之间不留空格。
- 该行 `flex-wrap: nowrap`：金额与评分不压缩，成交量是唯一可收缩项（空间不足时省略号）。≤639px 时金额降到 15px、成交与评分用 11px、「成交」缩为「售」，实测四种视口组合均无溢出、无截断。
- 服务标题只允许一行，超出省略；公司名称同样 `nowrap` + 省略号。两条都已用超长文案做过极限验证。
- 被省略的字段（标题、卖点、公司名）在悬停 1.5 秒后用 tips 显示完整内容；未截断时不出提示。tips 用 `position: fixed` + portal 渲染，避免被卡片的 `overflow: hidden` 裁掉。见 `src/components/EllipsisTip.tsx`。
- 评分仍保留「悬停满 3 秒出现『客户评分』tips，键盘聚焦时立即出现」。原来扫在标签底上的光线随标签一起移除；如果需要文字本身也有扫光，需要另加文字级扫光。
- 卡片正文间距在基础层与两套 V2 网格分别收紧；金额行与商家行各再加 4px 上下间距（`card-bottom` margin、`provider` margin）。
- 商家行：公司图标改为 Phosphor `Buildings` **线性**图标，颜色继承文字（`--color-text-secondary`），不再有浅蓝底方块、不再用首字。公司名与分割线的间距用 `padding-top` 控制（`padding-block: 8px 4px`）——只加 `margin` 只会把分割线本身推开，文字仍贴着线。
- 「电话」是与公司名称同一行的**文字幽灵按钮**：无边框、`--control-radius` 圆角矩形，默认透明，hover 只填充 `--color-primary-soft` 并加深文字；不再用下划线，也不在卡片上另开浮层。
- 缺省封面图标只保留图片框与山峦，右上角不再有品牌色圆形角标。
- 整卡可点用「链接包住内容」实现，**不再使用透明覆盖层**：覆盖层会让浏览器开发者工具（F12 选取）只能选到空链接，也挡住鼠标选字。现在封面与信息区在 `<Link>` 内，商家行（含「电话」按钮）在链接之外的 `service-card-foot` 里，因此按钮不嵌套在链接内，点击按钮也不会跳转。
- 注意：卡片整体是链接，所以鼠标拖拽选字会被浏览器当作链接拖拽/点击（原生行为，不是样式限制）；需要取文案可以用双击选词或开发者工具。
- 弹窗话术遵守「不制造平台背书」：只说号码由服务商发布、报价与交付由双方直接商定、平台不参与交易承诺；不出现「认证／优选／及时响应」等表述，也不展示店铺徽章。
- 演示模式不渲染 `tel:` 外呼入口，并在弹窗内标注「演示号码」。原型数据中的号码是真实号段，不能当作真实服务商被外呼；正式模式（非演示）才提供拨打动作。

## 风格与维护

样式集中于 `src/styles/showcase.css`，新增语义 token：媒体缺省底色、专题正文、Banner 强调色、商品价格色与内容宽。沿用原 React/Radix 组件基础，不安装新 UI 框架。V2 使用完整横幅、清楚的文字层级、紧凑商品陈列和局部业务切换；不沿用 V1 的矢量装饰 Banner。

颜色与动效服务于内容：Banner 深色缺省底与暖色文字，服务卡白底，商品价格适度暖色强调，业务选中状态使用主题色。动效限制为切换淡入、图片微缩放和按钮反馈。业务栏与产业栏切换有实际内容变化；专题导航可定位区块。

本轮沿用原型三类服务券的示例金额，仅出现在演示模式并标明示例，点击可查看说明，未实现发券/核销。正式构建显示活动分类，不展示演示金额。后续活动系统接通前，不把本地按钮当成真实优惠领取。

## 交接后下一步

先以真实 Banner 和商家宣传图验收视觉，再扩展企业服务的发布/消费同源模型。保持已有支付与履约需求，逐项核对原型流程，不继续用猜测替代规格、店铺、订单和验收规则。

## 导航与精致度追加修订

客户确认 V2 方向后，本轮仅细化视觉并授权补齐导航空页面。主导航按原型依次为首页、企业服务、数智金融、商品交易、智慧物流、产业资讯、AI 赋能、个人中心。产业地图放在顶部辅助栏，帮助入口保留。新增路由 `/finance`、`/procurement`、`/logistics`、`/news`、`/ai`、`/map` 均使用 `BlankModule`：视觉内容为空，保留统一导航、页脚和页面标题。首页业务入口同步跳转到对应页面。

- 主导航桌面高 58px、手机高 54px；辅助栏分别 24px / 22px。Logo 图形桌面 32px，文字两行间距 1px。
- 品牌主蓝现为 `#2460d2`，通过 token 统一。依据最新反馈，按钮使用纯色与柔和投影，撤回纵向渐变和顶部内高光。
- 全站主操作按钮共用 6px 圆角、40px 基础高度；导航入口使用紧凑 34px 尺寸，主次按钮共用交互逻辑。弹窗中的按钮也纳入统一样式。
- 样式统一层 `controls.css` 在页面样式之后加载；后续调整品牌与阴影改 `tokens.css`，调整控件规则改此统一层，不继续在单页复制新的按钮风格。
- 首页保留已确认的深色图片位、暖色文字和内容结构，只优化边线、轻投影、字重及选中反馈。
- 1099px 以下主导航折叠；小屏菜单两列，可用点击菜单项、点击外部或 Escape 关闭。吸顶专题栏通过 `--header-height` 对齐主导航。

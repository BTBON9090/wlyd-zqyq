# 政企园区客户端 · 前端试点

基于工作区原型，重构 **登录注册、企业入驻、首页、企业服务与个人中心**，用于视觉选型、业务流程验收及后端联调。项目为真实 React / TypeScript 前端，已有正式静态构建能力。

**交付边界：** 前端页面与交互已实现；当前没有真实后端、短信、审核、电子签章、支付服务。开发和预览模式提供明确标识的本地演示；正式模式只调用 API，不以演示数据冒充线上业务。真实业务上线必须完成下方「上线前需要提供」中的对接。

**导航与控件更新：** 顶部导航已按原型补齐；数智金融、商品交易、智慧物流、产业资讯、AI 赋能及产业地图专区暂为内容空页面；首页已增加金融、采购与物流专题，个人中心已有独立新版页面。桌面主导航高 58px，Logo 两行间距 1px。全站按钮、输入和导航样式统一维护在 `src/styles/controls.css`，基础品牌蓝为 `#2460d2`。

**最新版本：** V2 已延伸至企业服务推荐、服务大厅、服务详情、个人中心、登录注册与企业入驻。纯色蓝按钮、下划线主导航；首页增加数智金融、商品交易、智慧物流楼层。服务详情恢复原型多规格、店铺、案例、评价和分期履约信息。左下角悬浮按钮可切换 V1 / V2，默认 V2。图片区域统一改为可上传素材的真实图片位，缺图不再绘制 icon。详见 [V2 设计与图片配置](docs/HOMEPAGE_V2.md)。

## 1. 快速运行

推荐 Node.js 24 LTS（`.nvmrc`），最低 22.12。

```bash
npm ci
npm run dev
```

打开 `http://127.0.0.1:5174`。原来的 5173 端口已有进程，因此新试点使用 5174。

```bash
# 可独立部署的演示验收版本；输出 dist-preview/
npm run build:preview
npm run preview:demo
# http://127.0.0.1:4174

# 正式版本；输出 dist/，只使用真实 API
npm run build
npm run preview
# http://127.0.0.1:4173

npm run typecheck
npm run format
```

必须上传 **dist/** 的内容进行正式部署。**dist-preview/** 是验收版本，不能用于接收真实用户资料。不要将源码、archive、node_modules 或 `.env` 上传到静态站点。

## 2. 本次开发范围

| 路由                               | 功能                                                                    |
| ---------------------------------- | ----------------------------------------------------------------------- |
| `/`                                | V1 / V2 首页、运营 Banner、六大业务、服务券展示、精选服务与产业资源介绍 |
| `/login`                           | 短信登录／自动注册、密码登录、登录后回到原操作                          |
| `/register`                        | 验证手机号、设置密码、协议确认                                          |
| `/reset-password`                  | 验证手机号、密码规则与二次确认                                          |
| `/onboarding`                      | 创建企业、加入已有企业、邀请码入驻，资料确认与待审核状态                |
| `/services`、`/services/hall`      | 服务推荐与大厅独立布局、三级分类、关键词、价格、评分、排序、分页        |
| `/services/:serviceId`             | 商家相册、多规格与数量、价格联动、一次性/分期交付、案例、评价、FAQ      |
| `/services/:serviceId/order`       | 需求、附件、联系人、同意信息转交、提交结果                              |
| `/services/requests`               | 当前账号的服务申请记录                                                  |
| `/legal/service`、`/legal/privacy` | 沿用原型的协议阅读入口                                                  |

`/onboarding/:step` 保留原型路径可达性，目前统一进入新入驻向导；`/account/orders/services` 进入个人中心内的服务记录页。未知路由提供恢复入口。

**个人中心：** `/account` 总览；`/account/enterprise` 企业身份与审核状态；`/account/profile` 姓名编辑、手机号展示与密码重置入口；`/account/orders/services` 服务申请筛选与详情；`/account/demands` 已发布需求。其他订单、成员、角色路由提供有说明的空状态。

**本次没有开发：** 供应商端、商品交易/金融/物流完整业务、成员与角色权限执行、产业地图、资讯、AI 对话、优惠券领取、真实支付、合同签署与分期验收操作。首页新增楼层用于业务介绍；详情展示履约约定，未冒充真实交易能力。

## 3. 产品与流程决策

**2026-09-13 第一轮视觉修订（V1，供对比）：** 根据客户反馈，从松散的大留白布局调整为信息效率优先的企业门户。首页使用紧凑主视觉 + 账号工作区、常用类别与精选服务；增强蓝青渐变、暖色点缀、分层阴影和悬停反馈。保持文字清楚与操作直接，不用大型动画或装饰挤占服务信息。

**第二版优先原则：** 平台更接近商城与产业服务门户。原型大部分业务与流程需保留，V2 不以视觉简化为由删除运营图片、商家发布、规格、店铺或履约需求。下面对交易的简化描述是上一轮试点实现边界，不代表原型需求无效。

1. **先浏览，后登录。** 服务列表和详情公开；提交需求时才需要登录。登录保留服务目标地址。站外、协议相对地址和认证循环地址不能作为回跳地址。
2. **账号注册和企业入驻分开。** 注册成功可继续办理原任务；用户可以稍后补充企业信息。入驻审核中不阻断公开浏览与咨询。
3. **服务申请与交易订单区分。** 原型包含规格、合同及分期履约设计，属于有效业务要求。本次已恢复规格选择与履约信息展示，确认方案后进入需求申请。成功只表示申请已保存，不代表支付、签约、服务开始或审核通过。原 `/order` 路径为兼容保留，页面用词统一为「需求／申请」。
4. **不制造平台背书。** 不新增无来源补贴、成交额、AI 准确率、认证徽章或响应时间承诺。评分与成交仅使用商家发布数据。演示数据（服务名称、参考价格、示例封面、成交量概数）只出现在开发/验收构建；按客户要求，页面上的「原型 / 示例」提示文案已移除，演示属性改由本文档与右下角验收面板说明，正式构建只使用后端数据。
5. **入驻按实际身份分流。** 创建企业交园区审核，加入企业交企业管理员审核；邀请码不等于免审核。禁止在客户端自行授予管理员权限。
6. **避免假认证。** 本次不采集人脸、不模拟 OCR 成功、不声称电子签章生效。旧原型相关资料保留在归档中，未来由真实服务商接口和完整授权流程实现。
7. **导航对齐原型。** 已增加数智金融、商品交易、智慧物流、产业资讯、AI 赋能与个人中心；产业地图在顶部辅助栏。除本轮个人中心外，新增业务专区内容为空，办事指南通过「帮助与支持」打开。

详细的业务问题、开发阶段和后续优先级见 [开发计划](docs/DEVELOPMENT_PLAN.md)。

## 4. 技术架构与版本

安装时核对官方发布信息和 npm 稳定版本，使用确定版本及 lockfile，不使用 beta / canary。没有任何单一技术同时在所有项目中「最先进」且风险最低；本试点以 React 主流生态、静态部署简洁性和成熟交互组件为选择依据。

| 层次       | 技术                         | 用途                            |
| ---------- | ---------------------------- | ------------------------------- |
| UI         | React 19.3.0                 | 页面与交互                      |
| 类型       | TypeScript 7.0.2，strict     | 数据结构与接口约束              |
| 构建       | Vite 8.3.0、React 插件 6.1.1 | 开发、路由拆包、静态生产构建    |
| 路由       | React Router 7.18.3          | 地址、回跳、筛选参数            |
| 服务端状态 | TanStack Query 5.102.8       | 缓存、加载、失败与刷新          |
| 数据校验   | Zod 4.6.2                    | 表单与 API 响应运行时校验       |
| 对话框     | Radix Dialog 1.1.23          | 焦点约束、Escape、可访问名称    |
| 图标       | Phosphor 2.1.10              | 同一图标体系，regular / duotone |
| 样式       | 原生 CSS + 语义变量          | 主题、响应式、低依赖维护        |

选用 SPA，因为本期是用户操作型门户且需要简易静态部署，没有已给定的 SSR、公开搜索排名或 Node 服务需求。没有为了新技术增加第二套路由、状态库或动画框架。若未来正式要求服务详情 SEO，可在 API 和设计 token 不变的基础上评估 SSR。

参考：[React 官方版本](https://react.dev/versions)、[Vite 官方文档](https://vite.dev/guide/)、[React Router](https://reactrouter.com/)、[TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview)、[Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog)、[Zod](https://zod.dev/)。锁定版本以 `package-lock.json` 为准。

    commerce-v2.css     V2 多业务楼层、服务、账号与入驻布局

后续 AI 开发者先阅读本 README、[本轮 V2 交接](docs/V2_CONTINUATION.md)、`docs/DESIGN_SYSTEM.md` 与 `src/lib/models.ts`。页面只能通过 `gateway` 访问服务；不要在组件直接写 fetch，不要把 mock 数据引入业务目录。跨页查询放 TanStack Query，本地表单用局部状态；避免一个大型全局 store。

新页面优先复用 `Shell`、`Breadcrumb`、`Input`、`Modal`、`EmptyState`、`ServiceCard`，不要为同一按钮／表单复制新外观。不能把接口错误吞掉显示成功。交易权限、成员权限、审批结果、金额由后端确定，前端校验不构成安全边界。

## 6. 主题与图片

默认「政企蓝」，另外提供「生态青」「沉稳靛」。在右下角验收面板中切换。主题用 `html[data-theme]` 控制，偏好只保存一个主题名称，不保存身份数据。

换客户主题修改 `src/styles/tokens.css` 的语义变量；新增 `:root[data-theme="customer"]`，不要逐页替换颜色。中性色与错误／成功状态色不能随品牌色任意变换。色彩和间距规则详见 [设计规范](docs/DESIGN_SYSTEM.md)。

图片分两类。首页运营 Banner 与三张服务示例封面已提供本地生成的主视觉：源码在 `design/media/`，执行 `bash design/render-media.sh` 重新渲染到 `public/media/`。业务宣传、地图展示和合作伙伴标识仍是等待真实素材的图片位。服务卡缺封面时使用缺省位：浅色底 + 专用图标 + 「暂无宣传图」上下组合；其他缺图位置使用纯色与文字。缺省位是空状态，不算宣传图；所有宣传图位置仍然禁止用图标或 CSS 立体装饰代替。

1. 首页配置：`public/content/homepage.json`，或通过 `VITE_HOMEPAGE_CONTENT_URL` 连接后台公开内容接口。
2. Banner 支持桌面/手机独立图片、每 6 秒自动轮换（悬停或键盘聚焦暂停、系统「减弱动态」时停用）与手动切换，以及 HTML 文案叠加与整图展示两种模式。
3. 商家封面从服务接口的 `image` 字段读取，本地预览可在 `src/dev/prototype/services.json` 的 `image` / `published.coverUrl` 为商品指定图片路径。
4. 图片放到 `public/media/`，配置使用 `media/文件名.webp`。服务卡建议 3:2；具体尺寸和字段见 [图片配置说明](docs/HOMEPAGE_V2.md)。
5. 旧原型图片保留在用户提供的 `客户端/public/` 和归档中，本轮没有将原型的 SVG 分类图拷回宣传位。

**金额数字字体：** 金额使用自托管的 D-DIN Exp（`public/fonts/d-din/`，Datto, Inc. 以 SIL OFL 1.1 发布，允许商用与嵌入，许可证原文随字体存放）。西文与数字走 D-DIN Exp，汉字单位回落系统中文栈；卡片金额按 semibold 请求，实际匹配到 Bold。该字体只有 400/700 两档，且数字为比例字宽，需要上下对齐的表格金额仍用系统字体。规则见 [设计规范](docs/DESIGN_SYSTEM.md)。

## 7. 演示与验收面板

`npm run dev` 和 `build:preview` 默认演示模式。右下角面板提供：

- 逐项跳过手机号、验证码、密码、重复密码、协议、企业名称、信用代码、营业执照、联系人、需求、邀请码、企业选择。
- 恢复全部校验；已认证企业、个人账号、游客状态切换。
- 下一次操作失败、空列表、加载失败与恢复正常。
- 三套主题。

需要真实验证短信流程时：填写示例手机号 → 获取验证码 → 输入 **123456** → 手动勾选协议 → 登录。验证码演示有效期 5 分钟、重发间隔 60 秒、最多 5 次错误；注册时可设置密码。邀请码为 **PARK2026**。不会发送短信或联系真实服务商。商品卡的「电话咨询」在演示模式只展示原型中的服务商号码并标注「演示号码」，不提供外呼入口，避免拨到真实号段；正式模式才渲染拨打动作。

演示账号和申请使用当前浏览器的 sessionStorage，刷新可保留，同源其他独立标签页不保证共享，关闭会话后可清空。演示密码只保存示例哈希值，不保存明文；这不是可用于正式身份验证的实现。服务草稿仅暂存需求文字，不暂存密码、验证码或附件。

文件类型、大小限制始终保留；跳过必填项不会允许危险类型上传。绕过只存在 `src/dev` 与开发上下文；生产通过 `__DEMO__` 编译期常量彻底剪除动态入口。不要仅通过 URL、localStorage 或 CSS 隐藏来保护验收面板。

## 8. 后端联调与部署

见 [API 契约](docs/API_CONTRACT.md) 和 [部署说明](docs/DEPLOYMENT.md)。

```bash
# 开发联调：.env.local 中设 VITE_DATA_MODE=api
API_PROXY_TARGET=http://127.0.0.1:8080 npm run dev

# 根路径正式部署
npm run build

# 子目录部署（Nginx 也需配置对应 fallback）
DEPLOY_BASE=/client/ npm run build
```

正式身份使用 HttpOnly 会话 Cookie + 服务端 CSRF token；不会从 localStorage 获取身份。变更请求携带 `X-CSRF-Token`，申请接口另带 `Idempotency-Key`。所有返回数据经过 Zod 校验；超时与 401/403/404/409/413/429 均有用户可理解的提示。

### 上线前需要提供

1. **API 与业务口径：** 短信账号体系、企业审核、企业列表、服务发布数据、附件存储、申请记录。API 必须实现真实鉴权、服务端校验与幂等。
2. **平台信息：** 正式园区名、企业服务平台名称、运营主体、服务联系方式、备案号。当前没有伪造备案号。
3. **协议：** 原型协议为验收内容，正式运营需确认主体、个人信息处理方式、保留期限、用户权利入口与版本记录。本项目没有提供法律审查。
4. **服务真实性：** 参考价格、供给方、服务范围由运营审核。前端显示周期不代表平台承诺。
5. **托管：** 正式域名、HTTPS、API 同源反代、SPA fallback；如公开搜索排名是硬要求，另行评估 SSR。

已执行验证见 [验收记录](docs/ACCEPTANCE.md)。这份记录区分「构建验证」「本地演示验证」和「尚未获得后端条件」，不将演示通过等同于线上交易完成。
